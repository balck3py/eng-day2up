# 基础设施加固与风险记录

## 音标覆盖率抽样（Task 10）

### 背景

dictionaryapi.dev 的数据源是 Wiktionary，质量参差 —— 并非每个词都能通过音频文件名的
`-us.` / `-uk.` 后缀区分出美英发音。`parseDictApi`（`src/lib/dict/dictapi.ts`）在缺失
一侧时优雅降级（回退到无标记音标，或干脆返回 `null`），绝不编造。这里记录一次真实的
覆盖率抽样，供后续判断"降级链路多久会被触发一次"。

### 方法

抽取常见虚词、常用词与几个已知美英发音差异较大的词（`schedule` `tomato`
`advertisement` `either` `neither` `privacy` `vitamin` `leisure` `route` `herb`）共
109 个词，对每个词请求一次 `https://api.dictionaryapi.dev/api/v2/entries/en/{word}`，
用 `parseDictApi` 解析后统计 `audioUs` / `audioUk` 是否非空，请求间隔 200ms 以避免触发
限流（首次未加间隔时曾观测到大量假性 404，加入间隔后核实为限流噪音而非真实缺词）。

抽样脚本 `scripts/check-phonetic-coverage.ts`（临时文件，已在记录完结果后删除，未纳入
仓库）与浏览器内联复现版本使用同一份 `parseDictApi` 逻辑。

### 结果（2026-08-08 实测）

```
总数 109 / 有美音 86 / 有英音 35 / 美英俱全 33 / 都没有 21
状态码分布 {"200":103,"404":6}
```

| 指标 | 数量 | 占比 |
| --- | --- | --- |
| 总词数 | 109 | 100% |
| 有美音（`audioUs` 非空） | 86 | 78.9% |
| 有英音（`audioUk` 非空） | 35 | 32.1% |
| 美英俱全 | 33 | 30.3% |
| 美英皆无（含未收录的 6 个 404） | 21 | 19.3% |

### 结论

**美英俱全比例 30.3%，低于 40% 的判定线** —— 大部分词（约 70%）只能显示单一音标
（绝大多数情况下是"只有美音"，因为 Wiktionary 词条录制的音频以美式为主，英式音频明显
更稀缺：86 个词有美音 vs 仅 35 个词有英音）。

这**不阻塞交付**：`getPhonetics` 与上层 UI 已按"有几个显示几个、缺失一侧不编造"设计。
但需要在此如实记录，避免后续把"页面只显示一个音标"误判为 bug —— 这是数据源本身的
已知限制，而非解析逻辑或缓存逻辑的缺陷。

### 单词级抽查：hello

作为最小可复现的抽样单元，另外核实了单一词 `hello` 的原始响应结构：

```json
[{
  "phonetics": [
    { "audio": ".../hello-au.mp3" },
    { "text": "/həˈləʊ/", "audio": ".../hello-uk.mp3" },
    { "text": "/həˈloʊ/", "audio": "" }
  ]
}]
```

三条 phonetics 中，第一条是无文本的澳式音频（`-au.`，被解析器归入"其余方言"，忽略），
第二条是英式音标+音频（命中 `-uk.`），第三条只有美式音标文本、**音频为空字符串**——
不含 `-us.` 也不含 `-uk.`，因此解析器不会把它当作有效的美式音频来源，只会在
`phoneticUs`/`phoneticUk` 都为空时把它当无标记音标兜底。也就是说，即便是官方示例词
`hello`，dictionaryapi.dev 也**不能**提供完整的、双侧都带音频的美英对照 —— 这与上面
109 词抽样得出的"英式音频明显稀缺"结论一致，进一步印证了"优雅降级而非编造"是必需的
设计，而不是过度设计。
