# Repository audit P2 fixes

Scope: the eleven P2 items from the repository audit. P1 changes are outside this release.

| Item | Resolution |
| --- | --- |
| Review retries and concurrent updates | Persist each event before delivery; keep its identity across retries; update the word under a PostgreSQL row lock and deduplicate events in the same transaction. Preserve newer review timestamps when older events arrive. |
| Wordbook truncated at the API row limit | Read stable, ordered pages and enrich dictionary data in bounded batches. A failed page returns an error rather than an incomplete list. |
| Wordbook search races | Abort superseded requests and ignore their results/errors/loading updates. Backfill refreshes the current search. |
| Lemma missing when its base form is also in the text | Merge both query batches before mapping every inflection. Fixed in web and desktop; mastery filtering follows the base entry. |
| Server translation continues after cancellation | Carry the request signal through acquisition, hedging and streaming, including word AI fallback and contextual explanations; response cancellation cancels the model. Cancellation does not trigger fallback or circuit-breaker failures. |
| Late word subtitles clear a native selection | Render stable word spans from the first sentence render; timing enhancement only updates their attributes. |
| Remote pronunciation starts after local fallback | Stop and unload failed/timed-out audio; a new pronunciation cancels the previous audio/request and prevents its fallback from running. |
| Concurrent AI cache insertion | A service-role-only RPC uses a per-word transaction lock and inserts only if the dictionary entry is still absent. Existing dictionary entries are retained. |
| Desktop lookup hides database errors | Check required Supabase query errors so callers can show the retry UI. |
| Desktop mixed-language text becomes a single word | Strip surrounding punctuation, not Chinese characters or digits. |
| Dictionary import repeats committed batches | Derive stable content keys, deduplicate within each batch, and upsert on the unique import key. |

## Database rollout

Apply `supabase/migrations/0004_reliable_writes.sql` before deploying the web code or running a new dictionary import. It adds review events, `mark_review`, `save_ai_entry`, and the nullable import key/index. It does not rewrite existing dictionary or wordbook records.

The review endpoint accepts old clients without an explicit event ID by deriving a stable identity from the original answer timestamp. Old persisted outbox items retain their existing queue key when sent by the new client.

The import script still requires an empty dictionary at startup to avoid mixing imported rows with historical rows that have no import identity. Existing duplicate dictionary rows are retained because they may be legitimate original dictionary entries.
