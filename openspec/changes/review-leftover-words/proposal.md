## Why

复习页的所有进度都只活在 React state 里：背完一轮攒下的生词，关掉页面、过一天再打开、或者登录过期被踢回登录页，就全没了，下次没法专门把「上一轮没记住的那批」拎出来再过。更糟的是判定写库是「发出去不管」的 —— 登录过期后 `/api/review/mark` 返回 401，页面毫无提示，这段时间的熟练度变化直接丢失。

另外，复习队列从不看熟练度：熟练度满 5 的词和新词一样每轮都出，「掌握了」在复习里没有任何效果（单词本上看到的「复习 N 次」是不封顶的复习次数，熟练度本身最多到 5）。

## What Changes

- **上一轮生词表**：新增数据库表，记录最近一次「常规复习」里答不出来的那批词。表里存的是**完整名单**，之后在「只练生词 / 全部再来 / 复习上一轮生词」里又记住了几个，名单也不减；只有下一次常规复习结算时才整批覆盖。常规复习一个生词都没有时不覆盖，名单保持上一份。
- **复习上一轮生词**：设置页在有名单时多一个入口「复习上一轮生词（N 个）」，把名单里的词完整过一遍，不受「攒够 N 个生词收工」限制，也不覆盖名单。
- **已掌握的词降频**：熟练度满 5 的词进入冷却期，距上次复习不满 14 天时不进常规复习队列（包括「上一批必修」和「今天背过的巩固词」）；冷却期满后重新可出，答对就再冷却 14 天，答错熟练度降到 4、回到普通队列。设置页显示有多少个词在冷却中。「复习上一轮生词」不受冷却影响。
- **中断续背**：进行中的那一轮（队列、题型、进度、判定）存进浏览器 localStorage。刷新、关页面、登录过期重新登录后回到复习页，提示「继续上一轮 / 结束这一轮」；结束常规复习的未完成轮次视同结算（有生词就写名单）。
- **判定不再静默丢失**：写库失败（401、5xx、断网）的判定进入本地待补写队列并在复习页提示条数；重新登录、页面重新加载或网络恢复后自动补写，补写时带上原本的作答时间。
- 不做：完整的 SM-2 间隔重复（`due_at` 等预留字段仍不启用）、多份历史生词表、桌面客户端的复习功能。

## Capabilities

### New Capabilities

- `review-leftover-words`：上一轮生词表的产生、覆盖规则与「复习上一轮生词」模式。
- `review-mastered-cooldown`：熟练度满值词的冷却期与重新出现规则。
- `review-session-resume`：进行中轮次的本地持久化与续背，以及写库失败的判定补写。

### Modified Capabilities

（无。`openspec/specs/` 现有规格都不涉及复习。）

## Impact

- **数据库**：新增迁移 `0003_review_leftover.sql` —— 表 `review_leftover`（`user_id`、`wordbook_id`、`created_at`，主键 `(user_id, wordbook_id)`，RLS 按 `user_id` 隔离，`wordbook` 删除时级联）。
- **新增接口**：`GET/PUT /api/review/leftover`（读名单 / 整批替换）。
- **修改接口**：`POST /api/review/mark` 接受可选 `reviewedAt`，用于补写时还原作答时间。
- **前端**：`src/app/review/page.tsx`（新入口、轮次类型、续背提示、补写提示）；新增 `src/lib/review/cooldown.ts`、`src/lib/review/session.ts`（本地轮次存档）、`src/lib/review/outbox.ts`（待补写队列），各带单测。
- **桌面客户端**：不涉及。
