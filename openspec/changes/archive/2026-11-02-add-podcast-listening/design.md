# Design

## Context

动机见 proposal.md。现有 Web 使用 Next 16.3.0、React 19.2.8、Tailwind；`NavBar.tsx` 是客户端导航；`src/proxy.ts` 与受保护接口负责登录和准入。阅读页通过 `api/fetch-page` 抓文本，但接口不处理 RSS 命名空间与目录，不适合直接当播客接口。当前单词发音模块面向 TTS，不提供可控的长期音频实例。

2026-11-01 实查固定 feed：17 期，每期有 GUID、pubDate、enclosure MP3、itunes:image 和 podcast:transcript（SRT，英文）。随后复查最新一期 `daily-news-2026-11-01`：有 `language=en` 和 `language=zh-CN, rel=captions` 两份 SRT，各 62 条，所有起止时间完全一致；目前其余 16 期未声明中文。最新一期 SRT 为毫秒时间戳、多行兼容的标准块，含说话人前缀与字幕间隙；MP3 请求 Range 返回 206。feed 和字幕允许跨域；feed 返回 `Cache-Control: public, max-age=31536000`。

已存在 `reader-document-loading` 的导航单行要求；实际 `NavBar` 当前使用 flex-wrap。这是既有实现与规格的差异，新增入口时需在共享导航内解决，保持原规格，无需修改阅读能力契约。工作区已有无关 `.DS_Store` 与 `.claude/worktrees/` 改动，不纳入本变更。

## Goals / Non-Goals

**Goals:** 一个详情仅拥有一个音频实例；播放模式与暂停状态分离；目录与字幕可独立测试，媒体可按范围跳转；数据错误不破坏其他模块。

**Non-Goals:** 不实现媒体剪切或重新生成音频，不实现后台播放器、跨页面持续播放、音频下载或整期字幕自动翻译，不新增播客数据表；选区翻译与生词收藏复用已有服务。浮窗发音不改变播客位置或模式，不新增全站音频仲裁。

## Decisions

### 1. 固定来源的数据层与页面

计划新增 `src/lib/podcast/`（feed 解析、SRT 解析、加载与类型）、`src/components/podcast/`，`/podcast` 与 `/podcast/[episodeId]`。用受保护的 GET `/api/podcast` 返回规范化目录，GET `/api/podcast/[episodeId]` 返回单期信息、按英文时间配对后的字幕及英文、中文、音频各自的资源状态。参数只接受节目标识，不接收任意 URL。接口再次做会话校验，沿用现有准入代理。

节目 ID 优先由 GUID 生成确定性 URL 安全标识，缺 GUID 时使用 enclosure URL 的确定性摘要；不采用数组下标。重复 ID 去重，缺标题使用日期或未命名节目兜底，缺日期排至末尾并显示日期未知。日期统一按 Asia/Shanghai 展示。

RSS 用支持命名空间的维护中 XML 解析库，禁用实体展开/外部实体，文本以 React 文本节点渲染；不使用正则解析 XML。解析库具体版本在实施前核实并锁定。原有 fetch-page 继续服务阅读页，避免改变其输入与响应契约。

资源仅允许 HTTPS `qiniu.aiquannei.com` 下 `/podcast/daily-news/` 的合法路径，无用户名密码或非标准端口；字幕地址来自已解析的节目，重定向逐跳复核且最多 3 跳。服务端请求 10 秒超时、文本最多 2MiB；不得由接口变成开放代理。图片与音频同样验证 URL 后交给浏览器，资源错误独立反馈。

### 2. 更新策略

目录请求和接口响应不使用持久缓存；上游请求要求重新验证，并加受控缓存破坏参数，避免源站一年有效期让 URL 始终命中旧目录。进入列表和手动刷新均重新请求，取消或忽略较旧的未完成请求。详情也通过同一目录加载器解析标识，不手工拼接资源文件名。

相比浏览器直取，服务端数据接口提供统一解析、错误和来源限制；相比直接套用默认 fetch 缓存，显式更新策略适应每日新增节目。上游 CDN 可能不区分查询参数，实施时需验证不同参数/重新验证后的响应，必要时由 feed 发布方配置短缓存或发布时刷新 CDN；应用不能保证取到源站未公布的内容。字幕先按需加载，不预下载所有期音频。

### 3. 双语资源选择与 SRT 时间轴

解析每种语言时统一为 `{ id, startMs, endMs, text }`，支持 BOM、CRLF/LF、多行文本，按 startMs 稳定排序。丢弃无法解析、非有限、负数、结束不大于开始的块并记录部分失效状态；无有效块时显示字幕不可用。保留原文与说话人，不另做自然句切分。遍历全部 transcript 节点并按 SRT MIME 与 language 选择英文及 zh-CN；英文优先精确 en，其次 en-*；中文精确 zh-CN，允许 rel=captions。同语言有多个候选时优先 captions、再按 feed 顺序稳定选取，不将中英节点顺序当语言依据。不通过替换文件名构造中文 URL。

两种语言独立抓取解析，中文失败不能让整个详情接口失败。以英文为基准按 `(startMs, endMs)` 精确匹配中文，生成 `{ id, startMs, endMs, englishText, chineseText? }`。不按编号或数组索引配对；同一时间键重复时取首个有效中文块，未匹配中文不渲染，部分匹配时提供中文部分不可用提示；英文失败时不拿中文替代主时间轴。相比依赖当前条目数一致，时间键匹配避免中文漏条后整体错位。重叠块用起点最靠后的有效块作为当前条，规则固定且可测。以实际 audio.currentTime 判断高亮，间隙无当前条；音频时长已知时拒绝超出时长的起点，结束边界取字幕终点与音频时长的较小值。

### 4. 播放状态与事件

详情客户端持有一个 HTMLAudioElement，拆分 mode（sentence / continuous）、实际媒体状态（idle / loading / playing / paused / ended / error）、目标 cue 与请求代次。

| 操作 | 单句模式 | 连续模式 |
| --- | --- | --- |
| 点击字幕 | 跳至该条起点，播放至终点暂停 | 跳至该条起点，随后持续播放 |
| 重复点击同一条 | 重播整条 | 重播整条后继续 |
| 暂停后点击字幕 | 重播并句末暂停 | 恢复连续播放，句末继续 |
| 暂停/继续 | 中途续播，句末结束后则重播目标条 | 从当前位置暂停/恢复 |
| 从头播放 | 切连续，从零开始 | 从零重新开始 |

页面初始 mode=sentence，不自动播放。模式选择器明确显示「单句 / 连续」，切换本身不启动暂停中的媒体。播放中切单句，以当前条为停止目标，间隙则暂停等选句；切连续则解除片段边界并继续。用户确认的“连续暂停后点句仍继续后面”是模式持续规则，不以 audio.paused 推断模式。

跳转等待媒体就绪并设置 currentTime；每次点播递增代次，清除旧边界调度，所有 play promise、loadedmetadata、seeked 回调核对代次，防止快速点选复活旧目标。play() 拒绝时保持实际暂停态并提供重试；ended 停于本期。卸载或切期时暂停并移除监听、调度和资源引用。

单句边界使用实际媒体时钟配合短周期边界检查及近终点定时调度，timeupdate 作为补充，不能单靠其低频通知。跳转/暂停/切模式时重新计算调度；前台正常播放以终点后最多 150ms 为验证标准。页面转入后台时单句模式主动暂停，避免浏览器节流跨过下一句；连续模式遵从浏览器媒体能力，不承诺后台不中断。

### 5. 详情与导航呈现

详情顶部放返回列表、标题、日期；紧邻字幕放模式、从头播放、播放/暂停和时间状态。每组先展示主要英文，再展示较小、较淡但满足可读性要求的中文。组内任一语言的点击或键盘激活统一触发英文 cue，使用同一原音频和同一高亮；可将双语文本放在同一可访问的点播控件中，但必须保留文本选择能力，并依照下面的选区手势保护抑制长按后的点播。

使用与播放器状态独立的 showChinese 展示状态，进入详情默认为 true；「显示中文」统一控制已配对中文显隐，不重建音频实例、不 seek、不触发播放或暂停，当前目标与高亮保持不变。旧节目无中文时开关不可用并提示暂无中文；中文抓取失败支持重试，未配对条目仅显示英文。

字幕行使用键盘可操作控件，当前条和键盘焦点分开呈现。第一版不强制自动滚动，避免用户阅读别段时被拉走。英文字幕缺失不阻塞连续播放器，中文缺失不阻塞英文；音频失败不阻塞阅读。

共享导航采用单行的局部可横向滚动入口区（登出保持可达），页面本身不溢出；同时回归阅读页 390px 单行约束。沿用现有色彩与排版，不新增独立主题。

### 6. 选中即翻译与顶部紧凑浮窗

范围按播客详情和现有 `/reader` 内容区共用交互处理（用户未单独回答范围问题，本规划采用这一默认范围）。不扩展到导航、输入框、其他业务页或浮窗自身。当前 `ReaderSelection` 要先按「译」，`SelectionPanel` 的句子内容包含难词；这些交互需替换。复用数据能力，避免直接复用完整 WordCard 导致徽章、收藏原句说明和大标题挤占空间。

使用 `selectionchange` 与约 250ms 稳定期，支持触摸长按、拖手柄、桌面拖选和键盘选区；有效英文选择限 2000 字，超长仅处理前 2000 字并提示。识别使用现有 isSingleWord；单词走 lookupWordClient，句段走 streamTranslate(en2zh)，保留已有本地模型和后端配置。句段不调用 fetchHardWords、不出现生词卡片。纯中文选择不发起英文查词/英译中；播客跨组选择只从英文节点提取文本，过滤辅助中文字幕和说话人标签以避免重复混入。

顶部浮窗使用 fixed，贴当前视口顶部并预留安全区，不随正文滚动、不改变文档布局，不使用遮罩或锁住页面。内容区按实际行高限制至最多 4 行（如 0.875rem 字号、1.5 行高，对应约 84px；随用户字体缩放等比例计算），短内容自然收缩，超出 overflow-y:auto。正文文字保持原样，浮窗文字稍小但清晰；仅保留紧凑工具行，不使用巨型词头或多行原文摘要。单词展示词头、中文释义、音标及紧凑发音/收藏/关闭控件；句段内容只显示中文译文，保留关闭与必要的加载/错误/重试反馈。内部滚动允许触摸和键盘，overscroll-behavior:contain 避免滚到边缘带动正文。

维护 selectionSnapshot（文本、位置和英文上下文）、请求代次与 dismissGeneration。浮窗内按键、点击、发音、收藏、复制及选择文本不参与正文 selectionchange 处理；浏览器因点击浮窗而收起原选区，也不能据此自动关闭或重查。单词收藏静默带入英文所在句，最多 500 字，不展示占空间的原句说明；播客上下文只来自英文字幕，不包含中文或其他句的 UI 文字。

监听实际正文滚动容器和页面的 scroll；来源是浮窗或其后代时忽略，正文滚动立即关闭并使在途结果失效。关闭不主动更改页面滚动位置或播客状态，也不靠清空浏览器选择来防止复开；记住被关闭选区的文本和范围，旧选区持续存在时不重开，只有新选择动作才可重新触发。内部滚动不关闭；关闭按钮、Escape 和外部点击也关闭。新选择替换当前查询，只有最新代次可显示结果；能传 AbortSignal 的请求取消，其他请求逻辑失效，不让迟到响应复活浮窗。现有翻译/查词客户端尚无统一取消参数，实施时补充可选取消支持并覆盖本地流式分支，保持原调用方兼容。

### 7. 选区与字幕点播隔离

字幕文本保持 user-select:text，不能在 pointerdown 无条件 preventDefault。每次手势记录起点、移动和选区变化；长按、拖选、拖手柄、滚动后的 click 均不启动字幕播放。正常短点击且未发生选区手势时沿用点播规则；有旧选区时首个用于收起选区的点击仅收起，不意外播放。键盘选区不触发播放，显式键盘点播操作不变。浮窗事件不冒泡到字幕点播逻辑。

浮窗开启、替换、显隐与关闭不控制播客，不 seek、不重建媒体实例；收藏与复制不影响正文位置和媒体状态。单词发音使用独立发音接口，不改变播客目标、位置、播放/暂停状态或模式；不自动播放发音，必须点击图标。内部操作测试应断言播客状态不变。底层正文滚动关闭浮窗同样不暂停播客。

## Risks / Trade-offs

- [原生选区菜单和移动浏览器合成 click] → 不禁止长按选择，快照保留查询上下文，逐手势抑制点播；在 iOS/Safari 实测选词、拖手柄与顶部浮窗操作。
- [自动选区请求连发或旧响应复活] → 稳定期、范围去重、请求代次、关闭屏障与可选取消；正文滚动关闭后旧选区不能立即重开。
- [SRT 与实际说话边界不一致] → 严格使用提供的时间段，人工抽听连续相邻及有间隙条目；不承诺自动校正上游时间轴。
- [浏览器调度、跳转精度及后台限制] → 媒体时钟、代次保护、前台边界验证，单句转后台主动暂停；实测 Safari/iOS 与桌面 Chromium。
- [CDN 长缓存] → 显式重新验证与受控破缓存请求，验证发布更新链路；发布方缓存策略仍可能需要配合。
- [中英文时间轴未来不一致] → 仅按完全一致的起止时间配对，不猜测或按序号平移；中文缺失或部分失配提示辅助字幕不可用，英文时间轴与播放维持原状。
- [源字段或资源变化] → 命名空间解析、稳定标识、独立降级、固定夹具测试，不以本次 17 期数量硬编码。
- [缺少本地 Next 文档] → 目前没有 node_modules/next/dist/docs，实施前安装锁定依赖，先读对应版本指南再写代码。规划阶段不安装项目依赖。

## Migration Plan

无需数据库迁移。按数据层、页面、播放器依次实现，使用 Vitest 夹具和 Playwright 模拟媒体事件验证，再抽测真实源与真实音频跳转。上线沿用现有 Web 部署；若需回滚，移除新增路由、组件和导航入口，并回退共享选区组件的交互调整；无播客数据迁移，已收藏的单词保留。

## Open Questions

以下均为可后续调整的界面偏好，不阻碍当前规格：日期最终视觉格式、占位封面样式。当前采用年月日与现有应用配色。
