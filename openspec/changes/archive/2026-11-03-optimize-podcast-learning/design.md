# Design

## Context

动机和范围见 proposal.md。本变更同时包含已上线翻译优化的补记及尚未实现的逐词起播，不能把前者的测试结果当成后者已经通过。

### 已上线基线

- `b1df5b2` / 合并 `cb8ad4f`：设备请求开关、受保护的配置接口、模型直连、初始化和错误提示。
- `d916fb6` / 合并 `46f1026`：设备模式单词始终请求 AI，取消先查词库、纠正词回查及自动写回。
- `fe7d8c0` / 合并 `9a2eb37`：配置保存在浏览器、取消五分钟过期和逐次配额请求，设置支持主动重新获取。
- 最终行为和验证见 `docs/device-translation.md`：545 项单元测试通过、2 项可选网络测试跳过；Chromium/移动 WebKit 的 10 项设备翻译页面测试通过；lint 无错误、7 条既有警告，生产构建通过；`9a2eb37` 已经 Vercel CLI redeploy 并指向生产域名。不是此次文档补记重新执行的测试。

### 逐词能力的实际输入和现状

2026-11-03 读取 [Daily News feed](https://qiniu.aiquannei.com/podcast/daily-news/feed.xml) 及该期三个实际声明的 SRT：英文句级 60 条、中文句级 60 条，60 组起止时间完全一致；[逐词文件](https://qiniu.aiquannei.com/podcast/daily-news/daily-news-2026-11-03.en.words.srt) 992 条，对应去掉说话人标签后的 992 个正文词，规范化比较后顺序一致。

两种英文时间不能按包含关系直接配对：词起点最大早于其所属句起点 841ms，末词终点最大晚于句级终点 459ms。例如第 3 条末词结束于 14.057s，句级终点为 13.787s。两份文件内部样本时间均正向且无重叠，但这只证明数据结构，不代表已听音验证准确性。

当前 `feed.ts` 会给英文 `rel="captions"` 加分，因此可能把新逐词文件选成主字幕。`PodcastPlayer` 的起播、停止和高亮均只使用句级 Cue，`PodcastDetail` 将整个字幕行作为点播目标；其 effect 依赖 cues 数组，直接把增强数据合并成新数组会重建播放器。`ReaderSelection` 已支持遍历英文块内文本，必须保持跨 span 的选区和上下文提取。

## Goals / Non-Goals

**Goals:**

- 一份变更准确区分“已实现并部署”和“待实现”，补齐目标、设计、行为规格及任务证据。
- 保持句级文本和双语配对的身份不变，为已知正文词附加可信的原音频时间；词级数据仅增强精确点播。
- 单句从点击词播到该句末词终点；连续模式从点击词继续后文，长按选词仍自动翻译。
- 逐词加载、文本定位和音频生命周期分离，旧剧集和部分坏数据可靠降级。

**Non-Goals:**

- 不生成新音频或新字幕，不调用 AI 做字幕对齐，不修订 feed 上的原时间；不增加固定提前量或 0.5 秒尾部补偿。
- 不增加单词独立循环、卡拉 OK 式逐词跟随、自动滚动、播放进度持久化或跨页播放。
- 不改节目顺序、四卡封面布局、选集路由、浮窗四行限制、底部默认折叠和 0.5–1.2× / 0.1× 档位。

## Decisions

### 1. 将翻译优化记录为已完成基线

补记最终实现而非保留已被用户否定的中间方案。`device-origin-translation` 新能力覆盖以下架构：

- 请求优先级仍为自定义模型优先，然后按开关选网站模型设备直连或原 Vercel 路径。`lookupWordClient` 在设备模式直接生成词条，`streamTranslate` 直接流式翻译，难词解释也直连。
- 配置 GET 仅负责首次或主动获取，检查登录、准入、同源、HTTPS 和配置有效性，HTTP 响应 no-store。取到的四个配置字段另由应用保存到 `deviceTranslationConfig`，不是浏览器 HTTP 缓存。
- `deviceTranslation.ts` 共享同页 pending，保存内存与 localStorage；刷新和新标签页读本地，不设定时刷新。存储被禁用时保留内存路径，损坏配置重新取。配置获取的 generation/AbortSignal 阻止清除后的迟到响应重新保存 Key。
- 初始化只在设备模式、没有自定义模型且没有有效配置时真正发起 GET；翻译前不再 POST 配置接口或消费网站配额。模型失败不自动重新取配置或改走 Vercel。
- 设置显示就绪状态、明示配置含 Key 的本地保存方式，并提供主动重新获取。切回 Vercel、登出或账户切换清除配置，跨标签事件使旧内存失效；收藏、发音等独立请求不属于翻译回退。

不恢复“单词先查词库”“五分钟有效期”或“逐次配额 POST”中间设计。设备 Key 在浏览器可读是用户已经明确接受的保存方式；首次配置权限与供应商自身计费不取消。`translation-scheduling` 仍约束服务端路径，不修改其内部配额、对冲和超时。

### 2. 三轨分类先于英文候选排序

在现有资源校验之后，按 SRT 格式和语言分类，再检查已声明 URL 的 pathname：英文 `.words.srt` 后缀归入逐词轨并排除出句级候选，其他英文仍作为句级候选。`rel="captions"` 不能独立判断粒度；在各自类别内保留语言优先级。URL 查询参数不影响后缀识别，不拼接、改写或探测未声明地址。

`Episode` 追加 `englishWords: string | null`。`english` / `chinese` 含义保持，旧节目没有逐词声明时为 null；同规则用于四节目，但不要求其他节目立即提供逐词轨。只有逐词而没有句级英文时继续按主字幕不可用处理，不重新拼句。

保持当前 HTTPS、主机和节目目录白名单、每跳重定向检查、10 秒超时、2MiB 文本上限、DTD 防护及文本渲染。避免放开任意字幕 URL 代理，也不扩大图片与静态资源缓存范围。

### 3. 先显示句级正文，再后台加载定位数据

主详情仍只等待原英文/中文资源，并返回逐词声明元数据；不把第三个可选文件加入阻塞主响应的 Promise.all。

新增同源 GET `/api/podcast/shows/[programId]/[episodeId]/words`，沿用 `podcastResponse` 的登录、准入和 no-store。服务端按所属 feed 的实际声明定位逐词轨，再调用原有有界文本加载和 SRT 解析；不接受用户任意 URL。响应包含 `sourceUrl` 和逐词 cues，失败由独立请求返回并在详情非阻塞处理。主响应声明没有逐词轨时不发此请求。

客户端在主详情可用后启动增强请求，按节目、剧集和已声明的逐词 URL 作为身份。响应 sourceUrl 与当前声明不一致时丢弃，提示重新加载，不把更新过程中两版字幕强行混用；文本对齐也必须通过。切集、退出或新一次加载使用 AbortController/代次保护。该额外请求会再次按 feed 确认资源，但在正文已经可读之后执行；本次不引入共享 feed 长缓存。

采用独立的 `usePodcastWords` 状态和 `Map<cueId, AlignedSentence>`，不改写详情的原 cues 数组，也不让新映射成为音频初始化 effect 的依赖。控制器通过显式更新定位表获取增强信息，已开始的播放段是时间快照，不被后台结果改变。加载失败保留正文和整句播放；仅失败或部分不可用时显示紧凑提示和重试，不增加顶部控制条。

替代方案：三轨一次性返回实现较少，但会让慢逐词资源延后正文；浏览器直接抓 SRT 又额外依赖源站 CORS。选择受保护的独立接口，复用已有资源边界。

### 4. 文本顺序对齐，时间仅用于限制候选

新增纯函数模块 `src/lib/podcast/words.ts`，输入原句级 cues 和逐词 cues，输出映射及逐句可用状态，不修改两份输入。每个映射词包含可见英文文本中的 UTF-16 `startOffset/endOffset` 和原 `startMs/endMs`；句级原 ID 与原起止时间始终保留。

1. 提取与界面相同的说话人前缀，剩余正文采用保留原字符偏移的空白分词。展示始终切原字符串，不用重组词数组生成正文。
2. 仅为匹配规范化大小写、常见弯引号和词外标点；词内撇号、连字符及数字形式保留，避免把不同词过度归一。独立标点保留原文；定位时跟随相邻所属词。
3. 在逐词序列上维护已消费位置。以句级起点前后 1500ms 查找候选首词，要求候选连续完整词序列唯一匹配、时间正向有序且末词在句级终点前后 3000ms 内；不能按 SRT 序号或严格时间包含关系归句。窗口仅做校验/消歧，不对音频加减时间；实施中真实数据发现第 5 条句级终点含 1903ms 额外静音，因此将原定句尾 1500ms 校验放宽为 3000ms 并补回归，起点限制与实际播放边界不变。
4. 用时间二分索引限定搜索，候选过多或存在多个同样可靠匹配时放弃该句，避免不受限全局二次复杂度。全句词序列完整匹配后一次接受，不对问题句启用不完整词图。
5. 失败句不错误推进全局消费位置，下一句重新按时间窗口和完整词序列定位；没有唯一可靠匹配时仅该句回退。异常偏移超过校验范围、缺词、增词、多词合一或时间不合法也回退，不用模糊拼写匹配、均分时长或 AI 猜测。

当前样本适合整句词序列验证；后续若源站改变分词合同，再通过独立规格变更扩展合词/拆词，不在本次引入不确定对齐。

### 5. 播放段与字幕身份分开

原 Cue 继续负责显示时间和中文配对。派生的 `AlignedSentence` 包含词映射和首词/末词时间；未对齐句没有覆盖范围。

控制器保存不可变的当前 `PlaybackTarget { cueId, startMs, endMs }`：

| 操作 | 起点 | 单句终点 | 连续模式 |
| --- | --- | --- | --- |
| 有完整映射时点英文词 | 所点词 startMs | 所属句末词 endMs | 从该词继续到本期结束 |
| 有完整映射时点中文、时间、空白或整句入口 | 本句首词 startMs | 本句末词 endMs | 从本句继续 |
| 无完整映射时点句内任意位置 | 原句级 startMs | 原句级 endMs | 沿用原连续播放 |
| 从头播放 | 音频 0 | 无 | 切为连续 |

使用整句首词起点与末词终点，让中文或时间入口也能读完整条，避免首词早于句级起点时仍漏掉开头。单句末词终点已由用户确认；不是固定加时，也不裁到下一句的旧起点。所有实际停止仍裁到已知音频时长。

同词反复点击重新建立同一 target 并起播；快速点击由既有 generation 防止旧 play/seek/pause 回调覆盖新目标。暂停不清除 target，中途继续从当前位置；自然结束后继续从 target.startMs 重播，所以点词片段不会自动扩大成整句。连续模式点词不创建新的停止限制，暂停后点词仍恢复连续。

当前条目标识优先采用仍有效的已选播放段归属，避免词跨旧句界时错亮邻句；连续播放查找派生的整句播放范围。若未对齐句的旧范围与已对齐邻句重叠，已验证的词范围优先，再采用最近开始的有效句。真正的间隙不提前亮后句。中文仍根据原句级时间配对，不受这个音频索引影响。

`select` 扩展可选词目标，`toggle`/错误重试使用当前 target 起点，`setMode` 使用当前位置所属有效句，保留原媒体实例、元数据就绪跳转、用户手势内 play 调用、倍速重申和后台单句暂停规则。逐词数据到达不修改当前 target；只有之后的新点播或显式模式选择才采用新表。

### 6. 保持自然正文和既有选区

在 `data-selection-english` 内用普通 span 标记可靠词范围，间隔、换行及未定位内容仍由原字符串切片渲染。用行级事件委托读取词索引，整个行只有一条播放分支，不让词事件再冒泡触发句首播放；不增加嵌套 button，也不对正文 pointerdown 调用 preventDefault，保留原生长按选择。

继续复用 `SubtitleGesture` 的短点击、450ms 长按门槛、8px 移动和选区/滚动阻断。点击旧选区用于清除时先阻断；长按松开后的合成 click、拖选手柄和页面滚动不得触发词点播。`ReaderSelection` 的英文块边界不变，验证跨 span、跨句选区和收藏上下文，不将中文、说话人或定位辅助标签混入文本。

键盘保留每行一个 Tab 入口。未选择词时 Enter/Space 播整句；行聚焦且无选区/修饰键时，左右键定位上一个/下一个词，Home/End 定位首末词，Esc 清除词定位并恢复整句入口；Enter/Space 播定位词。Shift 组合保留选区操作，不抢占。定位只改变焦点标记，不播放；名称说明当前目标，帮助文字排除在英文选区之外。

视觉沿用原色板、字号和双语层级；仅桌面 hover/键盘词定位显示轻微下划线或焦点，不把每词做成胶囊按钮，不增加恒定逐词高亮。说明文字按实际状态显示“轻点英文词从该词收听，长按或选中英文自动翻译”；无映射时保留原整句说明。

### 7. 测试与验收边界

- 先用合成夹具覆盖三轨声明顺序、普通 captions 主轨、同词重复、说话人、引号/缩写/连字符/数字、偏移跨句界、局部缺词后重同步和不确定降级；保留旧英文单轨和其他节目范围校验。
- 媒体时钟测试覆盖点末词起点晚于旧句尾、从词到末词暂停、自然结束重播片段、暂停继续、连续跳转、0.5/1.0/1.2×、快速切换及增强结果迟到不重建媒体。
- 隔离鉴权的 Chromium/移动 WebKit 页面验证实际点击词坐标、跨 span 原生选择、清除旧选区、双语点播、Dock、键盘和设备翻译无词库/配额请求。已有 E2E 中直接假定英文块 firstChild 是 Text 的选择助手需要改为 TreeWalker。
- 使用当前公开三文件验证 60 条主字幕与 992 词映射，再以真实 MP3 抽查开头、中间、末词及边界偏移；记录实际媒体时间误差与听感。自动化的移动 WebKit 不代替真实 Safari/iOS 原生长按和音频手势验收，无设备时对应任务保留未完成。

## Risks / Trade-offs

- [同语言新轨抢占主字幕] → 先分类再排序，三轨所有顺序的测试是实施第一项，不能只加 words 字段而保留旧评分漏洞。
- [时间轻微跨界导致错归句或截尾] → 文本完整序列建立归属，播放使用逐词首末时间，配对仍用原时间；不以旧句界裁断新末词。
- [缺词使后续全错位] → 一句一验证、唯一候选、单调消费和局部重同步，问题句整体降级。
- [后台增强重置播放] → 保持原 cues 引用及单一音频生命周期，定位表独立更新、当前播放段快照不变。
- [点词与选词竞争] → 复用手势门控和行级单次委托，不禁原生文本选择，真机长按单独验收。
- [新增可选请求开销] → 仅有声明时后台加载，正文先显示；维持受保护的源校验，不为减少一次后台 feed 查询引入陈旧共享缓存。
- [逐词文件仍可能与音频不准] → 不保证文件时间之外的声学准确性，用真实音频抽查并如实报告；本次不自动修字幕。

## Migration Plan

无需数据库或持久播放状态迁移。实施在 `codex/` 功能分支进行，先读本地 Next 指南，再依次完成轨分类、后台增强接口/对齐、控制器播放段和手势 UI。未提供逐词轨的节目全程沿用原句级行为。

通过单元、隔离浏览器回归、lint、类型/生产构建和 OpenSpec 严格校验后，再按既有授权流程合并、推送并用 Vercel CLI redeploy，检查实际部署提交及生产别名。回滚逐词增强时关闭增强请求和词命中，恢复句级播放；保留已上线的设备直连翻译和本地配置缓存，不一并回滚。

规划已完成，用户随后明确要求开始实施；实际完成情况以 tasks.md 及验证记录为准，不把规划文件齐备当作功能完成，不自动归档。没有未解决的产品边界问题。
